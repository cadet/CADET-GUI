# Synthetic Äkta-style characterization chain

Same convention as `examples/EXAMPLE_DATA.md`:
every file here is *synthetic*, generated by `examples/generate_characterization_chain_data.py`
from a real CADET-Process simulation, then reshaped to look like an Äkta/Unicorn export
(volume axis in mL, per-channel sampling, detector units, run-log phase markers) and noised.
None of it is measured data; every number is invented for this synthetic instrument.

The six CSVs and `manifest.json` exercise a two-step characterization chain end to end:
`cadetgui.characterization.comparison.Comparison` reads each CSV, aligns it to its process's simulated clock via
the `"Phase Elution"` run-log marker, and `cadetgui.characterization.stages`/
`cadetgui.characterization.runner` fit each step's stage. `manifest.json`'s `initial_store` and
each step's `truth` are a `cadetgui.characterization.parameter_store.ParameterStore` in `to_dict()` form, keyed by
CADET-Process parameter path.

## Step 1 — "Extra-column volume" (`stage="tubing"`, `tubing="tubing_pre_column"`)

Two replicate pulse-tracer runs, `System pulse 1 (UV)` and `System pulse 2 (UV)`, with the column bypassed and every periphery
segment but `tubing_pre_column` bypassed too. Read on the `"UV 1_280"` channel at
`tubing_pre_column.outlet`; the injected species is `SystemTracer`, one component per run's
recipe.

| Truth | Value |
|---|---|
| `flow_sheet.tubing_pre_column.length` | 0.42 m |
| `flow_sheet.tubing_pre_column.axial_dispersion` | 4.5e-7 m²/s |

Known (not fitted, in `initial_store`): `tubing_pre_column.diameter` = 0.8 mm.

## Step 2 — "Column packing" (`stage="bed"`, `include_particle_porosity=True`)

Column in line (Lumped Rate Model With Pores, no binding), carrying step 1's fitted
`tubing_pre_column` forward. Two small-tracer runs (`Small tracer pulse 1 (conductivity)`, `Small tracer pulse 2 (conductivity)`, species
`SmallTracer`) read on `"Cond"` at `tubing_detectors.outlet` (`tubing_detectors` in line, a known
small volume); two large-tracer runs (`Large tracer pulse 1 (UV)`, `Large tracer pulse 2 (UV)`, species `LargeTracer`) read on
`"UV 1_280"` at `column.outlet` (`tubing_detectors` bypassed). The large tracer is pore-excluded
via `initial_store`: `flow_sheet.column.film_diffusion["LargeTracer"] = 0.0`.

| Truth | Value |
|---|---|
| `flow_sheet.column.bed_porosity` | 0.36 |
| `flow_sheet.column.particle_porosity` | 0.68 |
| `flow_sheet.column.axial_dispersion` | 5.5e-8 m²/s |

Known (not fitted, in `initial_store`): `column.particle_radius` = 30 µm,
`tubing_detectors.diameter` = 0.5 mm, `tubing_detectors.length` = 50 mm (a small, known
detector-to-detector volume), `column.film_diffusion["SmallTracer"]` = 8e-5 m/s.

`tubing_pre_column`'s axial dispersion (species-indexed) is carried from step 1's `SystemTracer`
probe to `SmallTracer`/`LargeTracer` unchanged, and reused for `tubing_detectors` at the same
flow rate — the same chain handoff `CADETProcess.characterization.CharacterizeBed` needs.

## Shared setup

All six runs share one instrument: flow rate 8.3e-9 m³/s, a 20 µL sample loop (`Pulse Injection`
template, sample loop included), 50 mol/m³ tracer in the loop — an injected amount of 1e-6 mol,
used as every comparison's `normalization.target_area`. The Pulse Injection template has no
pre-injection equilibration phase available through `cadetgui.process_builder.build_process` (its
`c_buffer_a`/`c_sample`/`cycle_time`/`flow_rate` fields never reach `delta_t_equilibration`), so
every process injects at simulated `t=0`; the exported Äkta CSVs still start `PRE_OFFSET_S = 60 s`
earlier, as a real export would, and alignment (via the `"Phase Elution"` marker) crops that
lead-in the same way it would crop a real one.

Each detector channel is shaped independently: `"UV 1_280"` in mAU (small baseline, an arbitrary
response factor per mol/m³, sampled every 0.5 s), `"Cond"` in mS/cm (a baseline of several tens
of mS/cm with a small rise, sampled every 0.2 s), both with fixed-seed Gaussian noise. Only the
channel a comparison actually reads carries a real signal; the other is baseline and noise only,
matching the real instrument (every detector runs on every injection, but salt is not
UV-active and a 200 nm bead does not move a conductivity reading). `Small tracer pulse 1 (conductivity)` additionally
carries a sharp, narrow pre-injection dip on `Cond` — large enough to bias a whole-trace baseline
fit's lowest-2.5%-of-points threshold (`CADETProcess.calibration.fit_baseline`'s default),
narrow enough not to meaningfully distort the area-normalization integral — so its comparison
needs (and sets) an explicit post-peak `baseline_window`; every other comparison leaves it `null`
and uses the default whole-trace fit.

## Verified end-to-end

Every comparison's `cadetgui.characterization.comparison.Comparison.problems()` is empty (auto-detects as an
Äkta export, its channel and `"Phase Elution"` marker exist, its recipe builds, its solution
path resolves), and evaluating each one at the store its own step's truth was generated from
(`initial_store` plus step 1's truth, plus step 2's truth once carried forward) gives an NRMSE
within a few percent — consistent with the injected noise, not a misalignment or a bad
normalization. `Small tracer pulse 1 (conductivity)` needs its explicit `baseline_window`: without it,
`Comparison.build_reference` raises (too few points survive the default threshold within the
pre-injection dip), which is the point — this dataset is deliberately not clean everywhere.

Also verified: rebuilding each process from its recipe, `initial_store` and the relevant step's
`truth` (`cadetgui.process_builder.build_process` + `cadetgui.characterization.parameter_store.apply_store`)
reproduces this file's own generation exactly, since CADET-Core is deterministic for identical
input; see `tests/test_characterization_chain_data.py`.

## Regenerating

```
python3 examples/generate_characterization_chain_data.py
```

Deterministic (fixed seeds): re-running produces byte-identical files.
