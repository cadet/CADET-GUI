# Example datasets

Every file in `examples/data/` is *synthetic* — generated by running the exact
`ConfigurationWidget()` default process (or a known, named deviation from it)
through the real CADET-Process simulator, sampling the result, and adding a
small amount of noise. None of it is measured data. The point of writing down
exactly how each file was made is so you know what the "correct" answer is
before you fit it — useful for checking the Parameter Estimation tab actually
works, not just that it runs without error.

All three share the same base: `ConfigurationWidget()`'s plain defaults —
`LumpedRateModelWithoutPores` column, `Linear` binding, 2 components, flow
rate `1e-6`, `total_porosity = 0.72`, `axial_dispersion = 1e-8`,
`adsorption_rate = [0, 0]`, `desorption_rate = [0, 0]` (i.e. no binding at
all by default). Each row below only lists what was changed from that.

| File | Changed from defaults | Signal / Calibration | Window | Noise (seed) |
|---|---|---|---|---|
| `example_uv_signal.csv` | *(nothing — plain defaults)* | Outlet, Component sum, Beer-Lambert (`extinction_coefficient=5000 L/(mol·cm)`, `path_length=1 cm`) | 0–10 min, 0.1 min steps | Gaussian, seed `20260911` |
| `example_raw_signal.csv` | `total_porosity = 0.60` | Outlet, Component 1, no calibration | 0–10 min, 0.1 min steps | Gaussian (scale 0.15), seed `20260916` |
| `example_binding_signal.csv` | `total_porosity = 0.65`, `axial_dispersion = 2e-8`, `adsorption_rate = [0, 0.3]`, `desorption_rate = [0, 0.05]` | Outlet, Total (sum of both components), no calibration | 0–20 min, 0.1 min steps | Gaussian (scale 0.08), seed `20260917` |

All noise is clipped at `0` afterward (no negative signal values). Every file
has a `time_min,signal` header and reads directly with `DataImportWidget`
(first two columns, time already in minutes).

## `example_uv_signal.csv`

The Beer-Lambert calibration exercise: nothing about the underlying process
differs from the plain default configuration, only the *signal* is
transformed (`signal = concentration * extinction_coefficient * path_length`)
to simulate a raw UV280 detector trace instead of a concentration directly.
Pick **Calibration: Beer-Lambert**, enter `extinction_coefficient = 5000`,
`path_length = 1`, to convert it back and see it line up with the simulated
curve. Not meant for parameter fitting (nothing was perturbed to fit
*towards*) — it's the calibration-mechanism demo.

## `example_raw_signal.csv`

The simplest possible fitting exercise. `total_porosity` is the only thing
that differs from the default configuration (`0.60` vs. the default `0.72`);
`axial_dispersion` and the binding rates are untouched. Pick
**Calibration: None**, check only **Total porosity**, run — it recovers a
value close to `0.60`.

## `example_binding_signal.csv`

A genuine bind-and-elute scenario, four parameters away from the default
configuration: `total_porosity`, `axial_dispersion`, and Component 2's
`adsorption_rate`/`desorption_rate` (Component 1 is left non-binding, i.e. an
unretained tracer — like a salt front eluting near the void volume, ahead of
a retained protein peak). Signal is **Total** (both components summed, as a
non-selective detector would see them), no calibration.

Verified end-to-end (fitting from the plain default configuration, starting
`total_porosity=0.5`, `adsorption_rate=0.1`, `desorption_rate=0.1`):

| Parameter | True value | Recovered |
|---|---|---|
| `total_porosity` | 0.65 | 0.6509 |
| `adsorption_rate` (Component 2) | 0.3 | 0.2980 |
| `desorption_rate` (Component 2) | 0.05 | 0.0495 |

These three recover cleanly and are the recommended checklist for a first
try. `axial_dispersion` (true `2e-8`) is deliberately *not* in that
recommended set — checking it too converges to a plausible but wrong value
(~`6e-8`) alongside the other three, because a single noisy Total-signal
trace doesn't carry enough independent information to separate axial
dispersion's effect from porosity's (see `ai-docs/ARCHITECTURE.md`'s
parameter-estimation section for the general point — this is a real
identifiability limitation, not a bug). Fitting it usefully needs either a
cleaner (lower-noise / higher-resolution) reference or fixing the other
parameters first from an independent measurement, same as in a real
experiment.
